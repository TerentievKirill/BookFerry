# Архитектура BookFerry Server

## Структура проекта

```text
bookferry-server/
│
├── main.py              # Точка входа
├── requirements.txt     # Зависимости
├── .env                 # Настройки
├── README.md
│
└── app/
    ├── api.py           # HTTP API
    ├── models.py        # Pydantic модели
    ├── config.py        # Загрузка настроек
    └── services/
        ├── mail.py
        ├── flibusta.py
        └── telegram.py
```

---

# main.py

## Назначение

Точка входа в приложение.

Практически не содержит бизнес-логики.

```python
from fastapi import FastAPI
from app.api import router

app = FastAPI()

app.include_router(router)
```

Основная задача:

- создать FastAPI;
- подключить роуты;
- в будущем подключить middleware, логирование и т.д.

---

# api.py

## Назначение

Здесь находятся **все HTTP-ручки**.

Например:

```text
GET  /health
POST /search
POST /send-book
```

Каждая ручка должна:

1. принять запрос;
2. проверить входные данные;
3. вызвать нужный сервис;
4. вернуть ответ.

### ❌ Не должна

- скачивать книги;
- отправлять почту;
- работать с Telegram;
- содержать сложную бизнес-логику.

---

# models.py

Описание моделей запросов и ответов.

Например:

```python
class SearchRequest(BaseModel):
    title: str
```

или

```python
class SendRequest(BaseModel):
    email: str
    file: str
```

FastAPI автоматически проверяет входящий JSON.

---

# config.py

Читает настройки из `.env`.

Например:

```text
BOT_TOKEN=...
SMTP_HOST=...
SMTP_LOGIN=...
SMTP_PASSWORD=...
```

Все остальные модули получают настройки отсюда.

---

# services/

Вся бизнес-логика проекта.

Например:

## mail.py

```python
send_book(...)
```

Отправка книги по почте.

---

## flibusta.py

```python
search_books(...)
download(...)
```

Поиск и скачивание книг.

---

## telegram.py

```python
send_message(...)
```

Работа с Telegram API.

# Главное правило

Если поймал себя на мысли:

> "Сейчас прямо в api.py скачаю книгу..."

значит архитектура уже нарушается.

Правильно:

```text
api.py
    │
    ▼
flibusta.download(...)
```

---

# Пример

## ❌ Плохо

```python
@router.post("/search")
def search():

    requests.get(...)

    xml = ...

    send_email(...)
```

---

## ✅ Хорошо

```python
@router.post("/search")
def search(request):

    return flibusta.search(request.title)
```

Вся логика находится внутри `services/flibusta.py`.

---

# Когда меняется main.py

Очень редко.

Обычно только при добавлении:

- middleware;
- логирования;
- CORS;
- авторизации;
- подключения базы данных.

В 95% случаев работа идет в `api.py` и `services/`.

---

# Простое правило

| Если нужно... | Пишем в... |
|---------------|------------|
| Создать новую HTTP-ручку | `api.py` |
| Описать входной JSON | `models.py` |
| Прочитать настройки | `config.py` |
| Отправить письмо | `services/mail.py` |
| Скачать книгу | `services/flibusta.py` |
| Работать с Telegram | `services/telegram.py` |
| Настроить FastAPI | `main.py` |

---

# Идея архитектуры

```text
API
 │
 ▼
Services
 │
 ▼
Внешние сервисы
```

API ничего не знает о том, **как** скачиваются книги или отправляются письма.

Он только принимает запрос и вызывает нужный сервис.
